# Архитектура Memory Desk

## Обзор

```text
┌──────────────┐   ┌────────────────────────────────────────────┐   ┌──────────────┐
│ папка записей│──►│ meetings_process.py (фоновый процесс)      │──►│   Obsidian   │
└──────────────┘   │  ffmpeg → MLX Whisper → фильтр → Ollama    │   │ заметка +    │
                   │  (diarize → analyze → note)                │   │ стенограмма  │
                   └───────────────┬────────────────────────────┘   └──────┬───────┘
                                   │ статус в runtime/processing-job.json  │ чтение
                                   ▼                                       ▼
                   ┌────────────────────────────────────────────────────────────────┐
                   │ memory_desk (FastAPI, 127.0.0.1:8502)                          │
                   │  jobs · knowledge · storage · services · digest · integrations │
                   │  SQLite (статусы, люди, задачи)   Qdrant Local (смысловой поиск)│
                   └───────────────┬────────────────────────────────────────────────┘
                                   │ REST + SSE /api/stream
                                   ▼
                   ┌────────────────────────────┐
                   │ React-интерфейс (memory_desk/web)│
                   └────────────────────────────┘
```

Обработка записи выполняется **отдельным процессом**, поэтому сбой модели не роняет сервер, а интерфейс только читает состояние. Сервер ничего не знает о моделях Whisper; к Ollama он обращается сам — для чата, сводок и фоновой разметки говорящих.

## Модули сервера (`memory_desk/`)

| Модуль | Роль |
| --- | --- |
| `app.py` | REST API, SSE-поток `/api/stream`, раздача аудио с Range, защита (Host и заголовок `X-Memory-Desk`), фоновый наблюдатель |
| `core.py` | Общее состояние, перечитывание заметок, индексация и переиндексация в фоне |
| `knowledge.py` | Чтение заметок Obsidian, проекты и типы, Qdrant, поиск и ответы чата |
| `storage.py` | SQLite: встречи, задачи, решения, люди, резервные копии |
| `jobs.py` | Очередь обработки, 12 этапов с весами, процент и оценка времени, ошибки человеческим языком |
| `services.py` | Сборка данных для экранов, чат |
| `digest.py` | Сводки в чате: период и проект/человек из вопроса, факты записей, итог моделью по частям; без модели — структурный список |
| `llm.py` | Запросы к Ollama: JSON-режим, повтор, разбор обрезанных и «грязных» ответов |
| `diarize.py` | Говорящие по тексту: оценка моделью, формат меток `**Имя:** реплика`, перезапись стенограммы |
| `speakers.py` | Фоновая разметка готовых записей, привязка говорящих к людям |
| `voice.py` | Голоса: SpeechBrain ECAPA, разбиение записи по голосу, профили людей, сопоставление |
| `whisper_filter.py` | Фильтр «галлюцинаций» Whisper |
| `calendar_source.py` | Ближайшая встреча из ICS-файла или ссылки |
| `apple.py` | Календарь и Напоминания macOS через EventKit (PyObjC); подменяемый бэкенд для тестов |
| `integrations.py` | События рядом с записями, привязка к событию, двусторонняя синхронизация задач с Напоминаниями |
| `housekeeping.py` | Учёт места и очистка хранилища |
| `waveform.py` | Форма волны для плеера (ffmpeg + numpy) |
| `config.py` | Пути и настройки (`~/Library/Application Support/MemoryDesk/config.json`) |
| `main.py`, `__main__.py` | Запуск сервера (`python -m memory_desk`) |

## Принципы

- **Obsidian — источник правды для текста.** Заметки читаются и пересобираются из файлов; переименование заметки не ломает связи, так как у встречи стабильный ID. SQLite хранит рабочие статусы (черновик/подтверждено, проект, тип, связи), Qdrant — только индекс для смыслового поиска и может быть перестроен в любой момент («Переиндексировать»).
- **Всё локально.** Whisper, Ollama, эмбеддинги и ECAPA работают на устройстве. После установки модели берутся из `huggingface-cache/` и `ollama-models/`, приложение запускается с `HF_HUB_OFFLINE=1`.
- **Собственная Ollama.** Кабинет запускает свой экземпляр на `127.0.0.1:11435` с моделями внутри проекта и не мешает системной Ollama.
- **Один процесс на каталог Qdrant.** Qdrant Local открывает каталог одним процессом; если он занят, поиск работает из памяти, что отмечено в «Состоянии системы».
- **Защита.** Только `127.0.0.1`, проверка `Host`, обязательный заголовок для изменяющих запросов, валидация длины и формата входных данных, санитизация текста, попадающего в Markdown-заметки.
- **Устойчивость.** Этапы обработки сохраняют промежуточные результаты; ошибки модели не теряют стенограмму; сводки и чат без Ollama деградируют до структурных ответов.

## Данные

Пути и состав описаны в [README](../README.md#данные-и-конфиденциальность). Схема SQLite создаётся и мигрируется кодом `storage.py`.

## Интерфейс (`frontend/`)

React 18 + TypeScript + Vite. Роутер и состояние — собственные лёгкие (`store.tsx`, `router.ts`), без внешних библиотек состояния; графики — на SVG (`components/charts.tsx`, `viz.tsx`) с табличным видом у каждого графика. Сборка кладётся в `memory_desk/web`, поэтому для обычной работы Node.js не нужен. Светлая и тёмная темы задаются токенами в `styles.css`.

## Тесты

`tests/test_api.py` поднимает сервер на временном наборе данных (`make_fixture.py`) с заглушкой эмбеддингов (`MEMORY_DESK_FAKE_EMBED=1`), подменяет Ollama, EventKit и кодировщик голосов. `tests/test_installer.py` запускает `install.command` с поддельными `brew`, `ollama`, `python` и проверяет порядок шагов и идемпотентность. `tests/make_stress.py` создаёт нагрузочный набор с крайними случаями.
