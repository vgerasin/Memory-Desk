# Дорожная карта и техническое задание на развитие

Что делаем дальше, в каком порядке и по каким критериям принимаем результат.
Состояние на сегодня и ограничения — в [STATUS.md](STATUS.md), описание готового — в [FEATURES.md](FEATURES.md).

**Размер работ:** **S** — несколько часов, **M** — день-два, **L** — неделя и больше, **XL** — несколько недель.
**Источник идей:** сопоставление с возможностями PLAUD (шаблоны саммари, Ask Plaud, артефакты, коннекторы, агент, MCP и CLI, настольное и мобильное приложения) — с учётом того, что Memory Desk работает локально и бесплатно.

## Принципы (не меняются)

1. **Всё локально.** Записи, стенограммы, вложения, отпечатки голосов не уходят в сеть. Облачных моделей нет.
2. **Всё, что выходит наружу, — только по явному подтверждению.** Письма, события календаря, задачи в «Напоминаниях», публикации. Любое такое действие попадает в журнал.
3. **Опасное выключено по умолчанию.** Доступ с телефона, запись через MCP, исходящие вебхуки включаются в настройках сознательно.
4. **Данные пользователя — его.** Выгрузка в обычные файлы (Markdown, PDF, HTML) всегда доступна; кабинет не запирает данные.
5. **В репозитории только код, документация и вымышленные данные.**

## Этап 0. Проверка на реальных записях (первым)

**Статус:** подготовлено — чек-лист `docs/STAGE0.md` и скрипт `scripts/stage0_report.py` (запуск «Проверка этапа 0.command»); пройти на Mac и вписать пороги.

В среде разработки нет Apple Silicon, Ollama и настоящих моделей, поэтому часть кода проверена только на заглушках. Размер: **M**.

| Что проверить | Как | Готово, когда |
|---|---|---|
| Установщик на «чистом» Mac | `install.command` на свежей учётной записи или после удаления `.venv` | запускается `start.command`, «Состояние системы» без красных строк |
| Whisper и Ollama | «Обработать новые» на одной короткой записи | в заметке есть стенограмма, резюме, задачи, решения |
| Календарь и Напоминания | «Разрешить доступ» в настройках | события видны в «Календаре», задача попадает в «Напоминания» |
| Голоса | «Подготовить голос», «По голосу» на записи с двумя известными людьми | люди узнаны, ложных узнаваний нет |
| Наложение голосов | запись, где перебивают друг друга | пометок немного, они попадают в настоящие перебивания |
| Устойчивость JSON модели | 10 записей подряд | доля ответов «Ollama вернул некорректный JSON» известна; при заметной доле — автоповтор с жёстким форматом |

Результат: подобранные `CLUSTER_SIM`, `MATCH_THRESHOLD`, `OVERLAP_*` в `voice.py`; список найденных ошибок. Заодно сравнить `qwen3:4b` с другой моделью на 16 ГБ по качеству задач и скорости.

## Этап 1. Быстрые улучшения (S каждое)

**Статус:** сделано в коде (1.1–1.3), ждёт проверки на Mac по `docs/STAGE0.md`, п. 3 и 7. Готовые отраслевые наборы слов — позже.

1. **Словарь терминов.** Файл слов, которые Whisper путает (КХД, ЦКП, Философт, имена): подсказка модели при расшифровке и замена по словарю в готовых стенограммах. *Готово:* термины на тестовой записи пишутся верно, правка словаря действует без перезапуска. Позже к нему добавятся готовые наборы по отраслям (ИТ и данные, финансы, право).
2. **Автозапуск обработки и уведомление.** Наблюдение за папкой PLAUD, по окончании уведомление macOS «запись готова, проверьте 3 задачи». Включается в настройках. *Готово:* файл, брошенный в папку, обрабатывается без нажатия кнопок.
3. **Резервные копии по расписанию** с ограничением числа копий. *Готово:* копия появляется сама, лишние старые удаляются.

## Этап 2. Ежедневная польза (M каждое)

**Статус:** сделано в коде (2.1–2.4), ждёт проверки на ваших записях: пороги похожести серий и замен подбираются по живым данным.

1. **Утренняя сводка.** Просроченное, обещанное вам, встречи на сегодня с «главным к встрече»; на «Сегодня» и одним уведомлением.
2. **Зависшие задачи.** Подсветка задач без движения больше двух недель или без срока; массовое «закрыть / перенести / отклонить».
3. **Серии встреч.** Повторяющиеся встречи складываются в линию: что изменилось с прошлого раза, какие вопросы висят третью встречу подряд.
4. **Расхождения между решениями.** Новое решение противоречит старому в том же проекте: кабинет предлагает отметить старое «Заменено». Решение принимает пользователь.

## Этап 3. Больше из одной записи (шаблоны, взгляды, ответы, закладки)

### 3.1 Библиотека шаблонов (3–5 штук) — M
- **Что.** Набор шаблонов итогового документа: «Планёрка», «Встреча один на один», «Совещание с решениями» (по умолчанию — нынешняя структура), «Интервью», «Лекция или обучение». Шаблон выбирается при обработке записи, по умолчанию его подсказывает тип записи.
- **Как.** Шаблон — файл (`templates/*.yaml`): название, разделы, инструкция модели по каждому, порядок, подпись. Шаблоны пользователя лежат рядом и не затираются при обновлении. Создание своего шаблона по текстовому описанию — через модель, с предпросмотром.
- **Готово, когда:** на одной стенограмме три разных шаблона дают три разных по форме заметки; разделы «Задачи» и «Решения» остаются в формате, который читает кабинет (иначе их не увидит реестр).
- **Риск.** Малая модель (4B) хуже держит сложную структуру: нужны проверка результата и откат к стандартному шаблону.

### 3.2 Несколько саммари на запись с разным фокусом — M
- **Что.** К записи добавляются «взгляды»: «только решения», «только задачи по людям», «вопросы к заказчику», «риски», «для руководителя на 5 строк». Основное саммари не заменяется.
- **Как.** Каждый взгляд — отдельный раздел заметки с пометкой источника (шаблон/фокус, дата, модель); пересчитывается по стенограмме, не затирая правки пользователя. В интерфейсе — вкладки взглядов внутри записи.
- **Готово, когда:** добавление и удаление взгляда не меняет остальную заметку; взгляд попадает в поиск и чат.

### 3.3 «Сохранить ответ в Obsidian» — S
Кнопка под ответом чата: ответ с источниками и таймкодами сохраняется как заметка в выбранную папку Obsidian (внутренние ссылки на записи), без дублей при повторном нажатии. *Готово:* заметка открывается в Obsidian, ссылки на записи работают.

### 3.4 Подсказки уточняющих вопросов — S
После ответа чата показываются 2–3 вопроса, которые можно задать дальше (по найденным источникам и открытым вопросам записи). По клику вопрос отправляется. *Готово:* подсказки не повторяют заданный вопрос; без модели показываются шаблонные («Что решили?», «Кто отвечает?»).

### 3.5 Закладки на стенограмме — M
- **Что.** Пометка важного места по таймкоду во время прослушивания или чтения: кнопка и клавиша, короткий комментарий, цвет. Список закладок записи, переход по клику.
- **Как.** Хранятся в SQLite и в заметке отдельным разделом «Закладки» (`⏱ 00:12:30 — текст`), чтобы переживали потерю базы. Закладки учитываются в «главном к встрече», протоколе и поиске.
- **Готово, когда:** закладка переживает «Переиндексировать» и восстановление копии; правка стенограммы не сдвигает её.

## Этап 4. Материалы и экспорт

### 4.1 Экспорт документов — M
- **Форматы (решено):** PDF, Markdown, HTML и **DOCX**. Для протокола, сводок, ответов чата, артефактов и досье. DOCX — редактируемый вариант для отправки коллегам; таблицы, заголовки и нумерация сохраняются как стили Word, а не картинки.
- **Как.** Единый шаблон оформления для PDF и HTML (шрифты, шапка, нумерация страниц), HTML самодостаточный (без внешних ресурсов), Markdown — тот же, что в Obsidian. Решение по движку PDF принять в начале этапа: `WeasyPrint` (нужны системные библиотеки) или печать из встроенного окна приложения (этап 11).
- **Готово, когда:** протокол длиной в 5 страниц выгружается во все четыре формата без обрезанных таблиц и с кириллицей; HTML открывается без интернета; DOCX открывается в Word и Pages без «кракозябр» и с работающими заголовками в оглавлении.

### 4.2 Карта как PNG, SVG, OPML — M
- **Как.** Карта строится из дерева `MapNode`, которое уже есть; SVG рисуется собственным генератором (без браузера и Mermaid CLI), PNG — из него; OPML — прямая выгрузка дерева для импорта в XMind/MindNode/OmniOutliner.
- **Готово, когда:** карта на 40 узлов читаема в PNG (минимум 2000 пикселей по ширине), SVG масштабируется без потерь, OPML открывается в стороннем приложении.

### 4.3 Артефакты: служебная записка, бриф, follow-up письмо — L
- **Что.** Три новых вида материалов по записи, проекту или человеку. **Каждый пункт имеет таймкод** (`⏱ 00:12:30`) со ссылкой на место в записи — чтобы проверить перед отправкой.
  - *Служебная записка* — адресат, суть, обоснование, решения, что просим.
  - *Бриф* — цель, контекст, договорённости, сроки, ответственные, открытые вопросы.
  - *Follow-up письмо участникам* — краткие итоги и задачи по людям.
- **Как.** Каждый факт берётся из уже извлечённых решений, задач и цитат стенограммы; модель только формулирует. Редактирование в окне, сохранение в Obsidian, экспорт (4.1). Письмо — только **черновик** (отправка через этап 7, с подтверждением).
- **Готово, когда:** во всех трёх артефактах нет пункта без таймкода или с несуществующим; без модели создаётся структурный вариант.

### 4.4 Дайджест по проектам — M
Недельный и месячный дайджест одной кнопкой, в том числе как презентация. Шаблон оформления — тот же, что в 4.1.

## Этап 5. Вложения и распознавание текста

- **Что.** К записи можно прикрепить **текстовую заметку** и **фото доски, слайда, листа**. Текст с фото распознаётся локально и попадает в поиск, чат, протокол и «Основные темы».
- **Как.** Файлы хранятся рядом с записью (`attachments/<id>/`), в заметке — раздел «Вложения» со ссылками (`![[...]]` для Obsidian). Распознавание: системный движок распознавания текста macOS (Vision, через `pyobjc`) с запасным Tesseract. Поддержку русского на вашей версии macOS проверить в начале этапа. Перетаскивание файла, вставка из буфера, выбор камеры iPhone через «Непрерывность» — по возможности.
- **Готово, когда:** фото доски с рукописным и печатным текстом даёт текст, который находится поиском; удаление записи удаляет и вложения; фото остаётся на диске пользователя и не уходит в сеть.
- **Размер:** **L**. **Риск:** рукописный текст распознаётся заметно хуже печатного — показывать результат как «черновик распознавания» с возможностью правки.

## Этап 6. Журнал действий, блокировка PIN, «стереть запись целиком»

Этап идёт до предложений действий и записи через MCP: сначала средства контроля, потом возможности. Размер: **L** целиком.

### 6.1 Журнал действий — M
Локальный журнал (только добавление): что, когда, кто (кабинет, MCP, CLI, телефон), над чем, результат. Записываются: подтверждение действий (этап 7), отправка и создание черновиков, правки задач и решений, удаления, вход по PIN, включение доступа с телефона. Просмотр с фильтрами, экспорт в CSV. Содержимое записей в журнал **не пишется**, только идентификаторы и названия. *Готово:* любое действие, меняющее данные вне кабинета, оставляет строку.

### 6.2 «Стереть запись целиком» — M
Одна кнопка стирает: аудио (в том числе в архиве), заметку Obsidian, стенограмму, вложения, строки в SQLite (задачи, решения, закладки, наложения, отпечатки голосов записи), фрагменты в Qdrant, волновую форму, упоминания в резервных копиях — **с предупреждением, что копии удаляются отдельно** и выбором их очистки. Перед стиранием показывается список того, что будет удалено, и требуется ввод слова-подтверждения. *Готово:* после стирания запись не находится ни поиском, ни по ссылке; отпечаток голоса человека из других записей не страдает; в журнале остаётся строка о факте стирания без содержимого.

### 6.3 Блокировка PIN — M
Запрос PIN при открытии и после бездействия (время настраивается). PIN хранится как хэш (в Связке ключей macOS), ограничение числа попыток с задержкой. Блокировка распространяется на интерфейс и API; MCP и CLI используют отдельные токены. **PIN не шифрует файлы** — шифрование диска остаётся за FileVault, это будет прямо сказано в настройках. *Готово:* без PIN API отвечает отказом; экран блокировки не показывает содержимое (в том числе в переключателе приложений).

## Этап 7. Предложения действий после встречи (всё через подтверждение)

- **Что.** После обработки записи кабинет находит в стенограмме договорённости, которые можно превратить в действие, и **предлагает** их карточками:
  - «созвонимся в четверг в 15:00» → событие в Календаре на ближайший четверг, участники из записи;
  - «отправь Анне протокол» → черновик письма Анне с протоколом;
  - «поставь мне напоминание проверить доступ до пятницы» → задача в «Напоминаниях».
- **Как.** Модель выделяет намерение, адресата и время; относительные даты («в четверг», «через неделю») разрешаются кодом по дате записи, а не моделью. Карточка показывает, что именно будет сделано, источник (таймкод) и кнопки «Создать / Изменить / Отклонить». Календарь и «Напоминания» — через уже работающую запись EventKit; письмо — **только черновик** в приложении «Почта», отправляет человек сам.
- **Готово, когда:** без нажатия «Создать» не меняется ничего; создание события и черновика попадает в журнал (этап 6); дата «в четверг» всегда разрешается верно, неоднозначные формулировки уходят в «Изменить» без догадок.
- **Размер:** **L**. **Риск:** ложные срабатывания — поэтому карточки только предложения, порог по уверенности, лимит числа карточек на запись.

## Этап 8. Локальный MCP-сервер и командная строка

### 8.1 MCP-сервер — L
- **Что.** Локальный сервер по протоколу MCP, чтобы подключать архив к Claude и другим инструментам, не выпуская данные из компьютера.
- **Инструменты чтения (включены):** поиск по архиву со ссылками на источники, получить запись, список задач и решений с фильтрами, досье человека или проекта (этап 9), сводка за период.
- **Инструменты записи (по умолчанию выключены):** добавить заметку к записи, поставить в очередь файл на обработку. Включаются в настройках, подтверждаются в кабинете, пишутся в журнал.
- **Безопасность.** Только локальный адрес, отдельный токен, ограничения на объём ответа. Содержимое записей в ответах помечается как данные, а не как инструкции.
- **Готово, когда:** Claude Desktop через настройку MCP задаёт вопрос по архиву и получает ответ с источниками; запись без включения отклоняется.

### 8.2 Командная строка — M
`memory-desk ask "вопрос"` (ответ и источники в терминал), `memory-desk ingest файл.mp3` (в очередь обработки, с ожиданием по флагу), `memory-desk status`, `memory-desk list --since 7d`, вывод в JSON для скриптов. *Готово:* команды работают при запущенном и незапущенном кабинете (во втором случае сообщают, что сервер не запущен, и подсказывают команду).

## Этап 9. Автообновляемое досье человека и проекта — L

- **Что.** Страница-«досье»: ключевые факты, **зависшие вопросы** (повторяются или остаются без ответа более двух встреч), **действующие договорённости** (решения без отметки «Заменено» и открытые обязательства), последние изменения. Для человека и для проекта.
- **Как.** Собирается из уже извлечённых фактов, а не заново из стенограмм; обновляется после каждой обработки записи. Факты со ссылкой на запись и таймкод. **Правки пользователя закрепляются** и не затираются при обновлении. Короткое «о чём разговор» от модели — по желанию, без модели остаётся структурный вариант.
- **Готово, когда:** новая запись меняет досье минимум в одном разделе; закреплённый факт сохраняется; каждый факт открывает источник.

## Этап 10. Языки интерфейса

- **Языки (решено):** русский (сейчас), **английский**, **французский**, **немецкий**, **испанский**. Набор можно расширять: добавление языка — это один файл переводов.
- **Как.** Все тексты интерфейса, сообщений сервера и подписей выносятся в словари переводов; даты, числа, склонения по языку. **Язык интерфейса и язык заметок — разные настройки**: заметки и подсказки модели остаются на языке записи, чтобы не ломать разбор разделов («Задачи», «Решения»). Язык расшифровки выбирается или определяется автоматически.
- **Готово, когда:** весь интерфейс и ошибки переключаются без перезапуска; нет «вшитых» русских строк (проверка скриптом); длинные французские и немецкие подписи не ломают вёрстку (+30 % к длине).
- **Размер:** **L**. Переводы нужно вычитать носителем, машинный перевод — только черновик.

## Этап 11. Приложение macOS, быстрые команды, доступ с телефона

Цель: Memory Desk перестаёт быть «сайтом на localhost» и становится приложением.

### 11.1 Приложение macOS — XL
- **Что.** Отдельное приложение в «Программах»: собственное окно, значок в Dock, автозапуск сервера внутри, остановка при выходе, обновление, подпись и нотаризация, чтобы macOS не блокировала запуск.
- **Оболочка (решено): нативная на Swift** с окном веб-представления (интерфейс на React остаётся). Даёт строку меню, быстрые команды, Связку ключей для PIN, расширения «Поделиться», подпись и нотаризацию. Сервер на Python запускается внутри приложения как дочерний процесс. Отвергнуты: Tauri/Electron (тяжелее, хуже интегрируются), `pywebview` (мало системных возможностей).
- **Что понадобится.** Xcode и аккаунт разработчика Apple (для подписи и нотаризации вне разработки на своём Mac достаточно бесплатной подписи, но приложение придётся разрешать вручную).
- **Готово, когда:** двойной клик по приложению открывает окно и запускает всё нужное; чистая установка без Терминала; обновление с сохранением данных.

### 11.2 Меню в строке macOS — M
Значок в строке меню: ход обработки, «Обработать новые», «Спросить архив» (маленькое окно), ближайшая встреча и «Подготовиться», быстрая заметка к последней записи, закладка на текущем месте. *Готово:* всё, что нужно ежедневно, доступно без открытия окна.

### 11.3 Быстрые команды macOS — M
Действия для приложения «Быстрые команды» (App Intents): «Обработать новые записи», «Спросить архив», «Добавить заметку к записи», «Открыть записи за сегодня». Позволяют запускать по расписанию, с горячей клавиши и из Spotlight. *Готово:* команды появляются в «Быстрых командах» без ручной настройки.

### 11.4 Чтение с телефона по домашней сети (PIN) — L
- **Что.** Просмотр записей, поиск, чат и «Сегодня» с телефона по домашней сети (**только чтение** по умолчанию), установка как приложение (PWA).
- **Как.** Сервер слушает сеть только при включённом режиме; вход по PIN (этап 6.3), срок сеанса, ограничение попыток, список устройств с отзывом, режим только чтения, запись и удаление запрещены, в журнал попадает вход с каждого устройства. Для установки на телефон нужен защищённый адрес — способ выбрать в начале этапа: локальный сертификат (`mkcert` с установкой профиля) или частная сеть (например, Tailscale). **Наружу в интернет не публикуется никогда.**
- **Готово, когда:** с телефона в той же сети открываются «Сегодня», поиск и чат; без PIN доступа нет; отключение режима закрывает порт.
- **Риск:** самая чувствительная по безопасности часть плана; перед реализацией — отдельный разбор угроз.

## Сквозной трек D. Дизайн и визуальная часть

Дизайн идёт **впереди** разработки экранов, а не после. Всё новое проектируется один раз, в одной системе, на русском, английском и французском (длина текста), в светлой и тёмной темах.

### D1. Дизайн-система — до этапа 3
**Статус:** цвета сделаны. Принятая палитра «как в Things» и 5 тем (Things, Минерал, Лаванда, Песок, Роза; у каждой светлый и тёмный режим) перенесены в приложение: токены в `frontend/src/themes.ts`, переключатель «Оформление» в настройках, режим «Как в системе». Осталось из списка ниже: отступы, радиусы, анимации, страница-образец компонентов, проверка контраста AA по каждой теме, значок приложения.
- **Основа.** Токены (цвета, типографика, отступы, радиусы, тени), светлая и тёмная темы, состояния (обычное, наведение, нажатие, фокус, отключено, ошибка, загрузка), анимация (длительности и кривые), правила для пустых экранов и ошибок.
- **Компоненты.** Кнопки, поля, переключатели, вкладки, карточки, таблицы, всплывающие окна, уведомления, плитки метрик, графики, значки.
- **Иконки и фирменный стиль.** Значок приложения (под macOS, включая строку меню), логотип, цветовая палитра. Решение: развивать нынешний облик или менять — на первом показе вариантов.
- **Готово, когда:** принят документ дизайн-системы и страница-образец со всеми компонентами в обеих темах; контраст текста не ниже AA; все значения вынесены в токены, а не разбросаны по стилям.

### D2. Экраны этапов 3–8 — по мере этапов
Шаблоны и выбор шаблона; вкладки «взглядов»; закладки и линия времени записи; галерея вложений с результатом распознавания; карточки предложений действий («Создать / Изменить / Отклонить»); журнал действий; настройки (язык, PIN, приватность, MCP); диалог «стереть запись целиком»; досье; экран блокировки. Каждый — макеты для светлой и тёмной темы, состояния пустой/загрузки/ошибки, проверка с длинными подписями.

### D3. Приложение, строка меню, телефон — до этапа 11
Окно приложения и вход (первый запуск, «Добро пожаловать», проверка системы); всплывающее окно строки меню; значок и состояния значка (покой, идёт обработка, ошибка, есть что проверить); **телефонная раскладка** (одна колонка, нижняя навигация, крупные зоны нажатия, чтение стенограммы с аудио); экран входа по PIN; онбординг и пустые состояния.

### Порядок работы над дизайном
1. Сбор материалов: скриншоты текущих экранов, список проблем (что уже не нравится), примеры понравившегося.
2. Направление: 2–3 варианта общего облика на ключевых экранах (Сегодня, Запись, Чат) → выбор.
3. Дизайн-система (D1) → показ.
4. Экраны по этапам (D2) → показ → правки → передача в разработку.
5. Приёмка реализации по макету: сравнение скриншотов, проверка тем и языков.
